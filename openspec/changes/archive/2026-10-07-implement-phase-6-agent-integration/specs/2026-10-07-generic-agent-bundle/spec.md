# generic-agent-bundle Specification delta

Covers architecture section §44 (Generic Agent Integration
Profile) and §45 (Plugin Generation Pipeline). The
generic agent bundle is the catch-all integration path
for coding agents without a dedicated plugin package.
The bundle maximises compatibility through standard
MCP, Agent Skills, plain Markdown instructions and
optional A2A.

The packager emits:

```text
dist/generic-agent/
├── skills/
│   └── project-intelligence/
├── mcp/
│   ├── stdio-example.json
│   └── http-example.json
├── AGENTS.example.md
└── README.md
```

The bundle is generated, NOT maintained by hand; the
canonical sources are the Phase 6 Agent Skill and the
Phase 6 MCP server capability descriptor. Additional
agent-specific adapters MAY be added as separate deliverables
without changing this bundle.

## ADDED Requirements

### Requirement: generic bundle is generated, not maintained

The generic agent bundle MUST be generated by a code
packager from the canonical sources. The bundle MUST
NOT be maintained by hand; the canonical sources are the
Phase 6 Agent Skill and the Phase 6 MCP server
capability descriptor.

#### Scenario: packager regenerates the bundle

Given the canonical Agent Skill at
`distribution/skills/project-intelligence/SKILL.md` is
updated
When the packager runs
Then `dist/generic-agent/` is regenerated
And the bundled `SKILL.md` is byte-identical to the
canonical `SKILL.md`.

### Requirement: bundled Agent Skill

The packager MUST emit
`dist/generic-agent/skills/project-intelligence/` as a
snapshot of the canonical Agent Skill (including the
`SKILL.md` and the `references/` directory). The
bundled content MUST be byte-identical to the canonical
`distribution/skills/project-intelligence/`.

#### Scenario: bundled skill matches canonical

Given the packager runs
When the operator diffs the bundled skill against the
canonical skill
Then the two directories are byte-identical
And the SHA-256 of the bundled `SKILL.md` matches the
canonical content hash.

### Requirement: stdio and http MCP configuration examples

The packager MUST emit both
`dist/generic-agent/mcp/stdio-example.json` and
`dist/generic-agent/mcp/http-example.json` as reference
configurations. The stdio example MUST carry the
documented stdio launch command and environment
variables; the http example MUST carry the documented
HTTP endpoint and authentication contract.

#### Scenario: stdio example is documented

Given the packager runs
When the operator reads
`dist/generic-agent/mcp/stdio-example.json`
Then the file carries the documented stdio launch
command
And the file is marked as an example.

#### Scenario: http example is documented

Given the packager runs
When the operator reads
`dist/generic-agent/mcp/http-example.json`
Then the file carries the documented HTTP endpoint
And the file is marked as an example.

### Requirement: AGENTS.example.md instructions

The packager MUST emit
`dist/generic-agent/AGENTS.example.md` as a plain
Markdown instruction file the agent can ingest. The
file MUST cover:

- the MCP server endpoint;
- the canonical Agent Skill location;
- the §33 retrieval-first escalation policy;
- the version handshake contract;
- the approval-gated materialise workflow.

#### Scenario: AGENTS.example.md carries the documented sections

Given the packager runs
When the operator reads
`dist/generic-agent/AGENTS.example.md`
Then the file carries the documented sections
And the content is non-empty and consistent with the
canonical Agent Skill.

### Requirement: README documents the bundle

The packager MUST emit `dist/generic-agent/README.md`
that documents the integration. The README MUST cover
the bundle layout, the canonical sources, the
documented examples and the optional A2A configuration
the bundle does not enable by default.

#### Scenario: README documents the bundle

Given the packager runs
When the operator reads
`dist/generic-agent/README.md`
Then the README carries the documented sections
And the content is consistent with the bundled files.

### Requirement: deterministic build

The packager MUST be deterministic. Two consecutive
runs with the same canonical sources MUST produce
byte-identical artifacts. The determinism MUST be
enforced through the skill content hash.

#### Scenario: two runs produce identical artifacts

Given the canonical sources are unchanged
When the packager runs twice consecutively
Then the byte sequence of every file under
`dist/generic-agent/` is identical.

### Requirement: compatibility through standard MCP and Agent Skills

The bundle MUST maximise compatibility through standard
MCP, Agent Skills, plain Markdown instructions and
optional A2A. The bundle MUST NOT depend on a
vendor-specific plugin mechanism; the MCP and Agent
Skills components MUST be sufficient for any
Agent-Skills-compatible coding agent.

#### Scenario: bundle works with an Agent-Skills-compatible agent

Given an Agent-Skills-compatible coding agent with
no vendor plugin
When the agent reads `AGENTS.example.md` and the
canonical skill
Then the agent successfully registers the MCP server
and follows the §33 retrieval-first policy
Without requiring a vendor-specific adapter.

### Requirement: optional A2A compatibility note

The bundle MUST NOT enable A2A by default. The bundle
MUST defer the A2A adapter implementation to Phase 10.
When a Phase 10 A2A compatibility note ships, the
note MUST be plain Markdown and MUST NOT introduce
runtime dependencies the default container does not
already carry.

#### Scenario: A2A is deferred to Phase 10

Given the bundle is shipped
When the operator inspects the bundle
Then the A2A compatibility note is plain Markdown
And A2A is NOT enabled by default
And the bundle defers the A2A adapter to Phase 10.
