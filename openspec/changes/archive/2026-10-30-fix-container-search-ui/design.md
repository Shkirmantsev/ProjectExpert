# Design

The published retrieval generation remains the single search source. Readiness stays fail-closed during changes; HTTP preserves the recorded reason. Source catalogs follow published inventory. The existing inbox scanner contributes configured, confined source files to discovery and fingerprinting, with its byte limit and policy. Runtime chunks retain LOCAL_ONLY metadata and stay in ignored cache. Docling parses PDFs; a calling agent curates Wiki pages explicitly.

The static UI uses current backend model choices, polls accepted admin jobs, disables duplicate actions and renders state via aria-live/aria-busy. Chat endpoint settings become informational because there is no upstream LLM wiring. Unsupported delegation is reported unavailable. Open WebUI receives evidence with citations as JSON or a finite OpenAI SSE completion (role/content/finish/DONE); it performs no LLM call.

Verification uses real HTTP with controlled embeddings, browser JavaScript execution with a DOM harness, inbox incremental edit/removal and source provenance, and focused legacy suites. Actual deployment is observed read-only; upgrades use a newly built image, preserve model cache/config, and are documented rather than silently modifying another repository.
